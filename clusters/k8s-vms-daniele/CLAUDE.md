# k8s-vms-daniele — App-Specific Gotchas

Terse pointers to release.yml decisions that used to be inline comments — full rationale and any incident detail now lives in Confluence.

- `awx` — the ingress host is Cloudflare-Tunnel-fronted, not exposed via this Ingress's own LB status; requires explicit `external-dns.kubernetes.io/target` annotation (tunnel target from cluster-vars) to opt in correctly. See [Confluence: AWX](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/748584961).
- `awx-test` — Ascender is CIQ's commercially-supported AWX fork; this is a disposable rehearsal instance for an eventual production AWX->Ascender migration, now running on CIQ's official `ascender-operator` Helm chart (`ctrliq.github.io/ascender-operator`) rather than the community `awx-operator` chart production `awx` still uses. `crds: Skip` relies on this release's `AWX.spec` never using a CRD field the community chart's schema (which prod's `CreateReplace` release actually installs) doesn't have — verified as a strict superset as of the 25.6.2 chart swap, but re-check this before any future chart/CRD bump on either release, since a `Skip` release drifting past what's actually installed fails silently at apply time, not at plan time. `upgrade.force: true` is required and permanent: the operator Deployment's `helm.sh/chart` label selector changes on this swap, and Deployment selectors are immutable, so a same-named-release upgrade fails without it — this stays true in the revert direction too, so don't remove it once the rehearsal is over. See [Confluence: Ascender AWX Replacement Evaluation](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/789446657/Ascender+AWX+Replacement+Evaluation) (predates this chart swap — due for a short update).
- `cloudnative-pg-operator` — this is a different operator from kubenuc's Zalando postgres-operator convention (different CRDs entirely); `podMonitorEnabled` is left off since Prometheus Operator CRDs aren't confirmed present on this cluster. See [Confluence: CloudNativePG Operator](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/777551916).
- `error-pages-karakeep` — styled (`connection` theme) error pages via the official `tarampampam/error-pages` chart + Traefik `errors` Middleware (statusCodes `400-599`). **One release per consuming namespace**: Traefik rejects `<ns>-<name>@kubernetescrd` cross-namespace references unless `allowCrossNamespace` is on, and k3s's bundled Traefik isn't repo-managed, so each consumer namespace gets its own tiny Deployment+Service+Middleware; it lives in its own app dir (not `karakeep/manifests`) so `k3s-prod-test` can overlay it with `traefikMiddleware.enabled: false` — the ephemeral CI k3s has Traefik disabled, so the Middleware CRD is absent. An Ingress opts in via `traefik.ingress.kubernetes.io/router.middlewares: <ns>-error-pages@kubernetescrd`; only opt in browser-facing Ingresses (400-599 also replaces API/auth error bodies). The Middleware must exist before an Ingress references it, or Traefik 404s the whole router (no `dependsOn` is set because it would hang karakeep-only CI runs). Accepted risk: Traefik forwards the original request headers (cookies, `Authorization`) to the error-pages pod; the NetworkPolicy (Traefik pods only, no egress) is the mitigation. Unmatched-host 404s can't be styled this way (no router matched).
- `external-dns` — CF_API_TOKEN needs Reloader wiring to restart on secret rotation; `txtOwnerId` is permanent, changing it orphans every owned record; adoption is opt-in via annotation only. **Chart `>=0.22.0` renamed the default annotation prefix from `external-dns.alpha.kubernetes.io/` to `external-dns.kubernetes.io/`** (dropped "alpha") — every app's `target`/`cloudflare-proxied`/`managed-by` annotations, plus this HelmRelease's own `annotationFilter`, must use the new prefix (migrated repo-wide 2026-10-07, both clusters). Before that fix, a Renovate chart bump silently crossed this version boundary (live since at least 2026-09-12) and every app's `target` annotation went invisible to the ingress source, which fell back to raw `status.loadBalancer` node IPs — invisible on already-adopted hosts (Cloudflare rejects the resulting A-record overwrite because a CNAME already exists there) but created real, wrong `A` records for `karakeep`, the first newly-adopted host since the regression. See [Confluence: External DNS](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/774012929).
- `falco` — `falcosidekick.config.loki.extralabels` is **not** a static label mechanism — it promotes existing Falco output-field names, not arbitrary `key:value` pairs; static labels (e.g. `service_name`, to fix `unknown_service` in Grafana Cloud) go in the top-level `falcosidekick.config.customfields` instead, and never reuse the key `source` there (clobbers the real Falco event-source label). See [Confluence: Falco](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/748224513).
- `grafana-alloy` — required secret-key contract on `grafana-cloud-credentials`; collector capabilities must stay at chart defaults or the logs collector breaks; log-severity drop/relabel pipeline keeps active-series budget in check. See [Confluence: Grafana Alloy](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/748257281).
  - **`grafana-cloud-credentials` numeric usernames must stay quoted in 1Password**: `logs-username`/`metrics-username` need literal quotes around the digits (e.g. `"1396863"`), not bare numbers. Flux's `targetPath`+`valuesFrom` merge (`fluxcd/pkg` `chartutil.ReplacePathValue`) strips one layer of surrounding quotes and forces string type when present; unquoted, it type-infers the value to a number, which the `k8s-monitoring` v4 chart's map-based `destinations` handling (a `toYaml`/`fromYaml` round-trip needed since `destinations` became a map, not a list, in the chart's v4 schema) flattens to `float64` and reformats as scientific notation (`1.396863e+06`), breaking Grafana Cloud Basic Auth with silent 401s. This surfaced when PR #1462 (2026-06-04) migrated `targetPath` from array-index form (`destinations[1].auth.username`) to map-key form to match the new chart schema — unquoted values were harmless under the old v3 chart (which ranged the list directly, no round-trip) and only became load-bearing after that migration. The quoting lives only in 1Password, invisible from this repo, so don't "clean up" the quotes.
- `karakeep` — HelmRelease via the official `karakeep-app/helm-charts` chart (bjw-s `common` + `meilisearch` subchart); `karakeep` (web) is a `StatefulSet`, `chrome` a `Deployment`, `meilisearch` entirely subchart-owned. SQLite-on-`local-path` persistence, non-replicated, no backup story yet; not a CNPG consumer despite `cloudnative-pg-operator` being installed cluster-wide. Chart's default chrome image (`gcr.io/zenika-hub/alpine-chrome:124`) is unpullable (GCR billing error on the upstream mirror, confirmed 2026-10-06) — overridden in `release.yml` to karakeep's own `ghcr.io/karakeep-app/karakeep-chrome`, digest-pinned and tracked by a dedicated `.renovate/customManagers.json5` entry (split `repository`/`tag` fields, same gap class as the existing `velero` entry). `karakeep` (web) runs as root (`runAsNonRoot: false`) — its image's `s6-overlay` init needs root for `/run`; `ignore-check.kube-linter.io/*` annotations on it are deliberate. `meilisearch`'s subchart ships fully hardened already, no override needed. `NEXTAUTH_SECRET`/`MEILI_MASTER_KEY` come from 1Password via `valuesFrom` (`targetPath: secrets.karakeep.stringData.NEXTAUTH_SECRET` / `secrets.meilesearch.stringData.MEILI_MASTER_KEY`); the `karakeep` controller auto-restarts on rotation via the chart's own `checksum/secrets`, but the `meilisearch` subchart's `existingMasterKeySecret` doesn't, hence `meilisearch.podAnnotations` carries `reloader.stakater.com/auto`. Shipped via a two-stage rollout: stage 1 (PR #2118) bootstrapped the first account over `kubectl port-forward` with signups open and no Ingress; stage 2 closed signups, pointed `applicationHost` at `${KARAKEEP_HOST}`, and enabled the Ingress, after the companion `terraform/cloudflare-tunnel/` PR (#2117) added that hostname's `ingress_rules` entry. Stage 3 wired up AI tagging/summarization/vision against a self-hosted OpenAI-API-compatible endpoint (`inference.hetzner.com`), same secret-wiring pattern as `NEXTAUTH_SECRET`/`MEILI_MASTER_KEY` — one `karakeep-openai-api-key` 1Password item with both a `password` (API key) and a `url` (base URL) field, referenced by two `valuesFrom` entries (`valuesKey: password`/`valuesKey: url`) into two `secrets.karakeep.stringData.*` leaves; no new Reloader annotation needed — covered by the same `checksum/secrets` mechanism. `INFERENCE_TEXT_MODEL`/`INFERENCE_IMAGE_MODEL` names are confirmed to exist verbatim on the real endpoint (`GET /v1/models`, checked 2026-10-07); the text-vs-vision role assignment itself (MoE model for text, dense model for vision) is still a judgment call, not verified against actual capability. `INFERENCE_OUTPUT_SCHEMA` is set to `"json"` (chart/app default is `"structured"`, OpenAI strict JSON-schema mode — avoided, per the general concern that a self-hosted vLLM-style endpoint may not honor it reliably). Briefly tried `"plain"` to chase the `Error: Got no message content from OpenAI` failure described below, but that wasn't the cause (switching to `"plain"` alone didn't fix it — the real cause was the token budget, see below) — and a direct side-by-side curl test against the live endpoint (2026-10-07, same trivial prompt) showed `"plain"` actually used **more** completion tokens (1424) than `"json"`/`json_object` mode (953) for the same short answer, the opposite of the assumed "unconstrained is safer" intuition. Reverted to `"json"`, which also has real confirmed production tagging successes; `"plain"` has none. Don't re-try `"plain"` without new evidence. `EMBEDDING_ENABLE_AUTO_INDEXING: "false"` is deliberate — semantic-search embeddings were declined, meilisearch's full-text search is sufficient for now. `INFERENCE_JOB_TIMEOUT_SEC` is explicitly raised to `"120"` (chart/app default is 30s) — confirmed live on 2026-10-07 that a real re-tag run against this endpoint takes ~29-30s per bookmark, right at the default timeout boundary, causing repeated timeout-then-retry cycles even though the underlying inference call itself works correctly. `INFERENCE_CONTEXT_LENGTH`/`INFERENCE_MAX_OUTPUT_TOKENS` are raised to `"16000"`/`"8000"` (chart/app defaults are 2048/2048) — root-caused 2026-10-07: one specific bookmark's tag-inference call (`inferFromText`, the **text** model path, not vision — confirmed from `packages/shared/inference.ts` source, despite the bookmark also having an embedded image) consistently returned `Error: Got no message content from OpenAI`, most likely because `Qwen/Qwen3.6-35B-A3B-FP8` is a reasoning ("thinking") model that was exhausting the default 2048-token output budget on hidden reasoning tokens before producing a final answer (`finish_reason: length` with empty `message.content`) — the endpoint's own `/v1/models` reports `max_model_len: 262144` for both models, so karakeep's conservative defaults, not the model, were the bottleneck. Re-verify this specific bookmark tags successfully after this change; if it still fails, the next suspect is `OPENAI_REASONING_EFFORT` (unset here) to constrain reasoning depth directly rather than just giving it more room.
- `mcp-viewer` — bound SA token minted via `kubectl create token` defaults to a 2h TTL and expires silently, still requiring periodic regeneration; the MCP kubeconfig now reaches this cluster over a direct VPN address instead of Teleport's kube-access proxy, because Teleport separately enforces its own `kubernetes_users`/`kubernetes_groups` impersonation allow-list independent of K8s RBAC — a `kubectl auth can-i --as=` test run through Teleport can fail (or pass) without saying anything about the SA's real RBAC. See [Confluence: mcp-viewer](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/777814017) for both failure modes, the VPN-direct fix, and the corrected verification command.
- `proxmox-selfreg-shim` — hardened webhook front-door replacing Semaphore's old self-registration webhook (Semaphore fully decommissioned); HMAC-verified, rate-limited, replay-protected, egress-restricted via NetworkPolicy to AWX's internal Service only. Reuses the pre-existing `selfreg_webhook_secret` 1Password item. See `ansible/awx-selfreg-bootstrap`/`ansible/proxmox-selfreg` for the AWX-side half of this flow.
- `reloader` — needs the dedicated `readOnlyRootFileSystem` top-level flag (not `containerSecurityContext`) or the required `/tmp` mount is never added; UID pinned to house style (65532) instead of the chart's own default. See [Confluence: Reloader](https://fastnetserv.atlassian.net/wiki/spaces/IT/pages/777551893).
